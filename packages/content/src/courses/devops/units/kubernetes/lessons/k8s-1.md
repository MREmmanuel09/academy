# Kubernetes: orquestación de containers

Pods, deployments, services. El estándar de facto para correr containers en producción.

## ¿Qué es Kubernetes?

**Kubernetes** (K8s) es un orquestador de containers open source creado por Google. Maneja deployment, scaling, healing de aplicaciones containerizadas.

**Analogía**: si Docker es el \"container\", Kubernetes es el \"capitan del puerto\" que decide dónde van, los reinicia si fallan, escala según demanda.

### Conceptos clave

- **Cluster**: conjunto de máquinas (nodes) que corren K8s
- **Node**: una VM o máquina física donde corren containers
- **Pod**: la unidad mínima — 1+ containers que comparten red y storage
- **Deployment**: define cuántas réplicas de un pod, manage rolling updates
- **Service**: abstracción de red que da IP estable a un set de pods
- **Namespace**: partición lógica del cluster
- **kubectl**: CLI para hablar con el cluster
- **Control plane** (master): API server, scheduler, controller manager, etcd
- **kubelet**: agente en cada node que corre pods

### ¿Por qué K8s?

- Auto-healing: reinicia pods que mueren
- Auto-scaling: HPA escala según CPU/memoria
- Rolling updates: deploy sin downtime
- Service discovery: DNS interno
- Secrets management
- Multi-cloud / hybrid

## kubectl: el CLI

### Comandos esenciales

```bash
# Contexto y config
kubectl config get-contexts
kubectl config use-context prod
kubectl config current-context

# Cluster info
kubectl cluster-info
kubectl get nodes
kubectl get nodes -o wide

# Trabajando con objetos
kubectl get pods
kubectl get pods -A                # all namespaces
kubectl get pods -n kube-system
kubectl get pods --all-namespaces -o wide
kubectl get deployments
kubectl get services
kubectl get all                     # todo en el namespace actual

# Describir
kubectl describe pod mi-pod
kubectl describe node mi-node
kubectl describe svc mi-service

# Logs
kubectl logs mi-pod
kubectl logs -f mi-pod              # follow
kubectl logs mi-pod -c mi-container # container específico en pod multi-container
kubectl logs mi-pod --previous      # instancia anterior si crasheó

# Ejecutar comandos
kubectl exec -it mi-pod -- bash
kubectl exec mi-pod -- ls /app
kubectl port-forward mi-pod 8080:80 # acceso local

# Aplicar manifests
kubectl apply -f deployment.yaml
kubectl apply -f ./directorio/
kubectl apply -f https://example.com/manifest.yaml

# Borrar
kubectl delete pod mi-pod
kubectl delete -f deployment.yaml
kubectl delete deployment mi-app

# Editar en vivo
kubectl edit deployment mi-app
kubectl scale deployment mi-app --replicas=5
kubectl set image deployment mi-app web=mi-app:v2

# Contexto y namespaces
kubectl config set-context --current --namespace=mi-namespace
```

## Tu primer Deployment

### deployment.yaml

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: mi-app
  labels:
    app: mi-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: mi-app
  template:
    metadata:
      labels:
        app: mi-app
    spec:
      containers:
      - name: web
        image: nginx:1.25-alpine
        ports:
        - containerPort: 80
        resources:
          requests:
            memory: "64Mi"
            cpu: "250m"
          limits:
            memory: "128Mi"
            cpu: "500m"
        env:
        - name: ENV
          value: "production"
        livenessProbe:
          httpGet:
            path: /
            port: 80
          initialDelaySeconds: 5
          periodSeconds: 10
        readinessProbe:
          httpGet:
            path: /
            port: 80
          initialDelaySeconds: 2
          periodSeconds: 5
```

### service.yaml

```yaml
apiVersion: v1
kind: Service
metadata:
  name: mi-app
spec:
  type: ClusterIP       # default, solo interno
  selector:
    app: mi-app
  ports:
  - port: 80
    targetPort: 80
```

Tipos de Service:
- **ClusterIP** (default): IP interna del cluster
- **NodePort**: expone en cada node (puerto 30000-32767)
- **LoadBalancer**: provisiona LB en cloud
- **ExternalName**: CNAME a servicio externo

### Aplicar

```bash
kubectl apply -f deployment.yaml
kubectl apply -f service.yaml
kubectl get pods -l app=mi-app
kubectl get svc mi-app
```

## Puntos clave

- Kubernetes orquesta containers: auto-healing, scaling, rolling updates.
- kubectl es el CLI. Comandos: get, describe, logs, exec, apply, delete.
- Deployment define réplicas de pods. Service da IP estable.
- Resources requests/limits controlan CPU y memoria de cada container.
