# Storage, ConfigMaps y Secrets

Persistencia de datos, configuración externa, gestión de credenciales.

## ConfigMaps

**ConfigMap** almacena configuración no sensible como key-value. Se inyecta como variables de entorno o archivos.

```bash
kubectl create configmap mi-config --from-literal=DB_HOST=db --from-literal=DB_PORT=5432
kubectl create configmap app-config --from-file=app.properties
kubectl create configmap nginx-config --from-file=nginx.conf
```

YAML:

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: mi-config
data:
  DB_HOST: db
  DB_PORT: "5432"
  LOG_LEVEL: info
  nginx.conf: |
    server {
      listen 80;
      location / {
        proxy_pass http://backend;
      }
    }
```

Usar en pod:

```yaml
spec:
  containers:
  - name: app
    env:
    - name: DB_HOST
      valueFrom:
        configMapKeyRef:
          name: mi-config
          key: DB_HOST
    volumeMounts:
    - name: config-vol
      mountPath: /etc/nginx/nginx.conf
      subPath: nginx.conf
  volumes:
  - name: config-vol
    configMap:
      name: mi-config
```

## Secrets

**Secrets** son como ConfigMaps pero para datos sensibles (contraseñas, tokens, TLS certs).

```bash
kubectl create secret generic db-creds \\
  --from-literal=username=admin \\
  --from-literal=password=secretpass

kubectl create secret tls mi-tls --cert=tls.crt --key=tls.key
kubectl create secret docker-registry regcred \\
  --docker-server=my-registry.com \\
  --docker-username=user \\
  --docker-password=pass
```

YAML (base64 encoded — NO cifrado por default):

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: db-creds
type: Opaque
data:
  username: YWRtaW4=        # admin
  password: c2VjcmV0cGFzcw== # secretpass
stringData:
  api_key: "actual-value-here"
```

Usar:

```yaml
spec:
  containers:
  - name: app
    envFrom:
    - secretRef:
        name: db-creds
    # O específicos:
    env:
    - name: DB_PASSWORD
      valueFrom:
        secretKeyRef:
          name: db-creds
          key: password
```

> **Importante**: Los Secrets en etcd NO están cifrados por default. Habilita **Encryption at Rest** en el API server. Mejor aún, usa un secret manager externo (AWS Secrets Manager, HashiCorp Vault).

## PersistentVolumes

Los pods son efímeros, los datos no. **PersistentVolume (PV)** y **PersistentVolumeClaim (PVC)** abstraen el storage.

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: mi-pvc
spec:
  accessModes:
    - ReadWriteOnce    # RWO: un nodo a la vez
  resources:
    requests:
      storage: 10Gi
  storageClassName: gp3    # AWS EBS
```

Usar en pod:

```yaml
spec:
  containers:
  - name: db
    image: postgres:16
    volumeMounts:
    - name: data
      mountPath: /var/lib/postgresql/data
  volumes:
  - name: data
    persistentVolumeClaim:
      claimName: mi-pvc
```

### Storage Classes

Definen tipos de storage dinámicamente:

- **AWS EBS**: `gp3`, `io2`
- **GCP Persistent Disk**: `pd-ssd`
- **Azure Disk**: `managed-premium`
- **NFS**: para multi-attach
- **Local**: node-local, fastest

### StatefulSets

Para stateful apps (DBs) que necesitan identidad estable y storage persistente:

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: postgres
spec:
  serviceName: postgres
  replicas: 3
  selector:
    matchLabels:
      app: postgres
  template:
    metadata:
      labels:
        app: postgres
    spec:
      containers:
      - name: postgres
        image: postgres:16
        volumeMounts:
        - name: data
          mountPath: /var/lib/postgresql/data
  volumeClaimTemplates:
  - metadata:
      name: data
    spec:
      accessModes: ["ReadWriteOnce"]
      resources:
        requests:
          storage: 100Gi
```

Cada pod tiene nombre `postgres-0`, `postgres-1`, etc. y su propio PVC.

## Puntos clave

- ConfigMap: config no sensible, inyectable como env o volumen.
- Secret: para credenciales. Cifrado at-rest en etcd es crítico.
- PVC/PV: storage persistente. StorageClass provisiona dinámicamente.
- StatefulSet: para apps con estado (databases) que necesitan identidad estable.
