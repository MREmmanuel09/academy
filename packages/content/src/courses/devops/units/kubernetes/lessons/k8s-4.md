# Ingress, networking y service mesh

Exponer apps al exterior, Istio/Linkerd, network policies.

## Ingress

Un **Ingress** expone servicios HTTP/HTTPS al exterior. Es el equivalente a un reverse proxy (Nginx, HAProxy, Traefik) en K8s.

### Ingress controller

Necesitas un **Ingress Controller** corriendo:
- **ingress-nginx** (el más popular)
- **Traefik**
- **HAProxy**
- **AWS Load Balancer Controller**
- **GCP Ingress**

```bash
# Instalar ingress-nginx
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/controller-v1.9.0/deploy/static/provider/cloud/deploy.yaml
```

### Ingress resource

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: mi-app
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
    cert-manager.io/cluster-issuer: letsencrypt-prod
spec:
  ingressClassName: nginx
  tls:
  - hosts:
    - mi-app.example.com
    secretName: mi-app-tls
  rules:
  - host: mi-app.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: mi-app
            port:
              number: 80
      - path: /api
        pathType: Prefix
        backend:
          service:
            name: api
            port:
              number: 8080
```

### TLS automático con cert-manager

```yaml
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-prod
spec:
  acme:
    server: https://acme-v02.api.letsencrypt.org/directory
    email: admin@example.com
    privateKeySecretRef:
      name: letsencrypt-prod
    solvers:
    - http01:
        ingress:
          class: nginx
```

## Service Mesh: Istio y Linkerd

Un **Service Mesh** abstrae la comunicación entre servicios. Provee:
- mTLS automático
- Traffic management (canary, A/B, retry, circuit breaker)
- Observabilidad (métricas, traces, logs)
- Authorization policies

### Istio

```bash
# Instalar
istioctl install --set profile=demo -y

# Habilitar injection en namespace
kubectl label namespace default istio-injection=enabled

# Sidecar se inyecta automáticamente
```

VirtualService (canary):

```yaml
apiVersion: networking.istio.io/v1beta1
kind: VirtualService
metadata:
  name: mi-app
spec:
  hosts:
  - mi-app
  http:
  - match:
    - headers:
        x-canary:
          exact: "true"
    route:
    - destination:
        host: mi-app
        subset: v2
  - route:
    - destination:
        host: mi-app
        subset: v1
      weight: 90
    - destination:
        host: mi-app
        subset: v2
      weight: 10
```

### Linkerd (más ligero)

```bash
curl -fsL https://run.linkerd.io/install | sh
linkerd install | kubectl apply -f -
linkerd viz install | kubectl apply -f -
```

## Puntos clave

- Ingress expone servicios HTTP/HTTPS al exterior. Necesita un Controller (nginx, traefik).
- cert-manager automatiza TLS con Let's Encrypt.
- Service Mesh (Istio, Linkerd) añade mTLS, traffic management, observabilidad.
- Para la mayoría, Ingress + cert-manager es suficiente. Service Mesh es para microservicios complejos.
