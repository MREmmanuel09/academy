# Networking en Linux

ip, ifconfig, ss, netstat, DNS, firewall iptables/nftables.

## Configurar interfaces de red

### Comandos modernos (iproute2)

```bash
ip addr                         # muestra IPs (reemplaza ifconfig)
ip addr show eth0
ip addr add 192.168.1.10/24 dev eth0
ip addr del 192.168.1.10/24 dev eth0
ip link set eth0 up
ip link set eth0 down
ip route                        # tabla de routing
ip route add default via 192.168.1.1
ip route get 8.8.8.8            # por dónde saldría este destino
```

### DNS

```bash
cat /etc/resolv.conf            # servidores DNS
nslookup google.com
dig google.com                  # más detalle
dig +short google.com           # solo la IP
host google.com
```

Para configurar DNS:

```bash
# /etc/resolv.conf
nameserver 8.8.8.8
nameserver 1.1.1.1
search midominio.com
```

O usar **systemd-resolved** (`/etc/systemd/resolved.conf`).

### Hosts locales

`/etc/hosts` mapea nombres a IPs, tiene prioridad sobre DNS:

```
127.0.0.1   localhost
192.168.1.50 mi-servidor
```

## Conexiones y puertos

### ss / netstat - qué está conectado

```bash
ss -tulnp                       # TCP/UDP listening, no resuelve nombres, numérico, muestra proceso
ss -tnp state established       # conexiones TCP establecidas
ss -ltp 'sport = :80'           # quién escucha en :80

netstat -tulnp                  # versión clásica
lsof -i :80                     # archivos/procesos en puerto 80
lsof -i -P -n | grep LISTEN     # todo lo que escucha
```

### Probar conectividad

```bash
ping 8.8.8.8
ping -c 4 google.com            # solo 4 paquetes
traceroute google.com
mtr google.com                  # traceroute interactivo
curl -I https://google.com      # solo headers
curl -v https://api.com         # verbose
wget https://example.com/file.zip
```

## Firewall: iptables y nftables

### iptables (legacy)

```bash
iptables -L                    # listar reglas
iptables -A INPUT -p tcp --dport 22 -j ACCEPT    # permitir SSH
iptables -A INPUT -p tcp --dport 80 -j ACCEPT    # permitir HTTP
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -A INPUT -j DROP                        # bloquear el resto
iptables -I INPUT -s 1.2.3.4 -j DROP             # bloquear IP específica
```

**Cadenas**:
- INPUT: tráfico entrante al host
- OUTPUT: tráfico saliente del host
- FORWARD: tráfico que pasa por el host (routing)

**Targets**:
- ACCEPT: deja pasar
- DROP: descarta silenciosamente
- REJECT: descarta y notifica
- LOG: solo loguea

### nftables (moderno, Debian/Ubuntu nuevo)

```bash
nft list ruleset
nft add table inet filter
nft add chain inet filter input { type filter hook input priority 0 \\; }
nft add rule inet filter input tcp dport 22 accept
```

### UFW (Ubuntu simplificado)

```bash
ufw allow 22                    # permite SSH
ufw allow 80/tcp
ufw enable
ufw status
ufw deny 23                     # bloquea telnet
```

### firewalld (RHEL/CentOS)

```bash
firewall-cmd --list-all
firewall-cmd --add-service=http --permanent
firewall-cmd --reload
```

> **Cloud**: en AWS/Azure/GCP el firewall de OS importa MENOS porque el **Security Group** filtra antes. Pero siempre ten defensa en profundidad.

## Puntos clave

- `ip addr` y `ip route` son los comandos modernos (iproute2). ifconfig está deprecado.
- ss -tulnp muestra puertos en escucha y sus procesos.
- /etc/hosts tiene prioridad sobre DNS para mapeos locales.
- Firewalls: iptables (legacy), nftables (moderno), UFW (Ubuntu fácil), firewalld (RHEL).
