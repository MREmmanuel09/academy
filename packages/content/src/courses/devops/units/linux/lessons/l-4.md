# Usuarios, grupos y permisos

El modelo de seguridad fundamental de Linux. chmod, chown, sudo.

## Usuarios y grupos

Linux es **multi-usuario**. Cada usuario tiene un UID (User ID) único.

- **root** (UID 0): el superusuario, puede todo
- Usuarios normales (UID 1000+): poderes limitados
- Usuarios de sistema (UID 1-999): para servicios (www-data, mysql)

Los **grupos** permiten asignar permisos a conjuntos de usuarios.

```bash
whoami                    # tu usuario
id                        # tu UID, GID y grupos
useradd -m juan           # crear usuario con home
passwd juan               # cambiar password
usermod -aG sudo juan     # añadir juan al grupo sudo
groupadd developers       # crear grupo
groups juan               # grupos de juan
```

> **En servidores cloud**: tu primer usuario es `ubuntu` o `ec2-user`. Necesitas `sudo` para comandos de root.

## Permisos (rwx)

Cada archivo tiene 3 sets de permisos: **owner**, **group**, **others**.

```
-rwxr-xr-- 1 juan devs 1024 Jan 1 12:00 script.sh
↑ ↑↑↑ ↑↑↑ ↑↑↑
│ │  │  │  └─ otros: r-- (solo leer)
│ │  │  └──── grupo: r-x (leer + ejecutar)
│ │  └─────── owner: rwx (todo)
│ └─────────── hardlinks
└───────────── tipo (- archivo, d directorio, l link)
```

**Notación octal**:
- r = 4
- w = 2
- x = 1

`chmod 755 archivo` = rwxr-xr-x (típico en scripts)
`chmod 644 archivo` = rw-r--r-- (típico en archivos de config)
`chmod 600 archivo` = rw------- (solo owner, p.ej. claves SSH)

### chmod

```bash
chmod +x script.sh              # añade execute
chmod 755 script.sh             # octal
chmod u+w archivo               # user + write
chmod g-r archivo               # group - read
chmod a+x archivo               # all + execute
chmod -R 644 /var/www           # recursivo
```

### chown - cambiar owner

```bash
chown juan archivo              # cambiar owner
chown juan:devs archivo         # owner + group
chown -R www-data:www-data /var/www
```

### Umask - permisos por defecto

`umask 022` = archivos nuevos se crean como 644, directorios como 755.

## sudo y elevación de privilegios

**sudo** (\"superuser do\") permite ejecutar comandos como root sin cambiar de usuario.

```bash
sudo apt update
sudo !!                          # repite el último comando con sudo
sudo -i                          # abrir shell como root
sudo -u postgres psql            # ejecutar como otro usuario
sudo systemctl restart nginx
```

### El archivo sudoers

`/etc/sudoers` define quién puede usar sudo y qué puede hacer. Se edita con `visudo` (¡NUNCA con un editor normal!).

```
root    ALL=(ALL:ALL) ALL
juan    ALL=(ALL) NOPASSWD: ALL
%admin  ALL=(ALL) ALL
```

### Sticky bit, SUID, SGID (avanzado)

- **SUID** (`chmod u+s`): archivo se ejecuta con permisos del owner (ej. `/usr/bin/passwd`)
- **SGID** (`chmod g+s`): archivos nuevos heredan el grupo del directorio
- **Sticky bit** (`chmod +t`): solo el owner puede borrar sus archivos (típico en `/tmp`)

```bash
ls -la /usr/bin/passwd   # -rwsr-xr-x (SUID en passwd)
ls -la /tmp              # drwxrwxrwt (sticky bit)
```

> **Seguridad**: en DevOps, el principio de **least privilege** manda. Da a cada servicio solo los permisos que necesita.

## Puntos clave

- Linux es multi-usuario. root (UID 0) puede todo, usuarios normales tienen poderes limitados.
- Permisos son rwx para owner, group, others. chmod en octal (755, 644, 600).
- sudo permite elevación controlada. /etc/sudoers define las reglas.
- SUID, SGID y sticky bit son permisos especiales para casos específicos.
