# SSH y acceso remoto

Conectar a servidores, claves SSH, tunneling, configuración.

## SSH básico

**SSH** (\"Secure Shell\") es el protocolo estándar para acceder remotamente a servidores Linux.

```bash
ssh usuario@servidor
ssh usuario@192.168.1.10
ssh -p 2222 usuario@servidor    # puerto custom
```

### Configuración del cliente

`~/.ssh/config`:

```
Host mi-servidor
  HostName 192.168.1.10
  User ubuntu
  Port 22
  IdentityFile ~/.ssh/id_ed25519

Host prod-*
  User admin
  IdentityFile ~/.ssh/work_key
```

Ahora `ssh mi-servidor` conecta directamente.

### ssh-copy-id

Para añadir tu clave pública a un servidor:

```bash
ssh-copy-id usuario@servidor
```

### ProxyJump (bastion host)

```bash
# Conectar a un servidor privado a través de un bastion
ssh -J bastion@publico.internal@privado
```

En `~/.ssh/config`:

```
Host interno
  HostName 10.0.1.5
  User admin
  ProxyJump bastion

Host bastion
  HostName bastion.example.com
  User ubuntu
```

## Claves SSH

### Generar par de claves

```bash
ssh-keygen -t ed25519 -C "tu@email.com"
ssh-keygen -t rsa -b 4096            # RSA 4096 bits (legacy)
ssh-keygen -t ed25519 -f ~/.ssh/deploy_key -N ""   # sin passphrase
```

**Algoritmos** (en orden de preferencia):
- **ed25519** (recomendado): moderno, rápido, seguro
- **RSA 4096**: legacy-compatible, aún seguro
- ~~DSA~~: inseguro, no usar
- ~~ECDSA~~: sospechoso después de 2010, evitar

### Estructura

`~/.ssh/` debe tener permisos 700:
- `id_ed25519`: clave privada (permisos 600, NUNCA compartir)
- `id_ed25519.pub`: clave pública (compartir, va al servidor)
- `authorized_keys`: claves autorizadas (en el servidor, 600)
- `config`: configuración del cliente
- `known_hosts`: fingerprints de hosts conocidos

### ssh-agent

Maneja claves con passphrase sin tener que tipearla cada vez:

```bash
eval $(ssh-agent)
ssh-add ~/.ssh/id_ed25519
ssh-add -l                       # lista
```

### Hardening del servidor (sshd_config)

```
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
Port 2222
AllowUsers admin deploy
MaxAuthTries 3
ClientAliveInterval 300
```

```bash
sudo systemctl reload sshd
```

## Tunneling y port forwarding

### Local port forward (L)

```bash
ssh -L 8080:interno:80 bastion
# Accede a localhost:8080 -> bastion -> interno:80
```

Uso: acceder a un servicio que solo está disponible desde el bastion.

### Remote port forward (R)

```bash
ssh -R 8080:localhost:3000 servidor
# servidor:8080 -> cliente:localhost:3000
```

Uso: exponer tu servicio local a un servidor remoto.

### Dynamic port forward (SOCKS proxy)

```bash
ssh -D 1080 servidor
```

Configura tu navegador para usar SOCKS5 en `localhost:1080`. Todo tu tráfico irá cifrado por el túnel SSH.

### SCP y SFTP

```bash
scp archivo.txt usuario@servidor:/ruta/
scp usuario@servidor:/ruta/archivo.txt .
scp -r directorio/ usuario@servidor:/destino/

sftp usuario@servidor
sftp> put archivo.txt
sftp> get archivo.txt
sftp> ls
sftp> exit
```

**rsync sobre SSH** (la mejor opción para sincronizar):

```bash
rsync -avz -e ssh /origen/ usuario@servidor:/destino/
rsync -avz --progress -e ssh archivo usuario@servidor:
```

- `-a`: archive (preserva permisos, timestamps)
- `-v`: verbose
- `-z`: comprimir en tránsito
- `-P`: progress + partial (reanuda si se corta)
- `--delete`: borrar en destino lo que no está en origen (¡cuidado!)

## Puntos clave

- ssh usuario@host es la base. ~/.ssh/config te permite alias y atajos.
- Genera claves con ssh-keygen -t ed25519. NUNCA compartas la clave privada.
- ssh-copy-id instala tu clave pública. Ed25519 > RSA 4096 > ECDSA > DSA.
- Tunneling: -L local forward, -R remote, -D SOCKS proxy. rsync -avz para sincronizar.
