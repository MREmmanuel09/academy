# Procesos y servicios

Ver, matar, monitorear procesos. Systemd, journalctl.

## Procesos

Un **proceso** es un programa en ejecución. Cada proceso tiene un **PID** (Process ID) único.

```bash
ps aux                          # todos los procesos
ps aux | grep nginx             # buscar proceso
top                             # monitor interactivo
htop                            # top mejorado (instalar aparte)
pidof nginx                     # PID de un proceso por nombre
pgrep -f "python app.py"         # buscar por comando
```

**Estados de proceso**:
- R: Running
- S: Sleeping (esperando evento)
- D: Uninterruptible sleep (esperando I/O)
- Z: Zombie (terminó pero padre no recogió el estado)
- T: Stopped (Ctrl+Z)

### Señales - cómo comunicarte con procesos

```
SIGTERM (15)    Terminación educada - da tiempo a limpiar
SIGKILL (9)     Muerte inmediata - el proceso no puede ignorar
SIGHUP (1)      Hangup - tradicionalmente "recargar config"
SIGINT (2)      Ctrl+C
SIGSTOP (19)    Pausar
SIGCONT (18)    Reanudar
```

```bash
kill 1234                       # SIGTERM al PID 1234
kill -9 1234                    # SIGKILL
killall nginx                   # mata todos los nginx
pkill -f "python"               # mata por patrón
```

> **Regla**: intenta primero SIGTERM, espera unos segundos, luego SIGKILL si no responde.

## Background jobs

```bash
```bash
comando &                       # correr en background
jobs                            # ver jobs en esta terminal
fg %1                           # traer job 1 a foreground
bg %1                           # mandar a background
Ctrl+Z                          # suspender (SIGTSTP)
disown                          # desvincular del shell
nohup comando &                 # ignora SIGHUP, sobrevive al logout
```

### nohup y procesos persistentes

Para procesos que deben seguir corriendo tras cerrar sesión:

```bash
nohup python app.py > app.log 2>&1 &
```

- `nohup`: ignora SIGHUP
- `> app.log 2>&1`: redirige stdout y stderr a archivo
- `&`: corre en background

Pero para servicios reales, usa **systemd** (siguiente sección).

## Systemd - el manager de servicios

**systemd** es el sistema de init moderno. Maneja servicios, logs, mount points, timers.

```bash
systemctl status nginx          # estado del servicio
systemctl start nginx           # iniciar
systemctl stop nginx            # detener
systemctl restart nginx         # reiniciar
systemctl reload nginx          # recargar config sin reiniciar
systemctl enable nginx          # arrancar al boot
systemctl disable nginx         # no arrancar al boot
systemctl list-units --type=service   # todos los servicios
systemctl daemon-reload         # recargar configs de systemd
```

### Unit files

Los servicios se definen en `/etc/systemd/system/` o `/lib/systemd/system/`.

```ini
[Unit]
Description=Mi aplicación
After=network.target

[Service]
ExecStart=/usr/bin/python /opt/app/server.py
Restart=always
User=appuser
Environment=NODE_ENV=production
WorkingDirectory=/opt/app

[Install]
WantedBy=multi-user.target
```

### journalctl - los logs de systemd

```bash
journalctl -u nginx                     # logs de nginx
journalctl -u nginx -f                  # follow (como tail -f)
journalctl -u nginx --since "1 hour ago"
journalctl -u nginx -p err              # solo errores
journalctl --since today                # logs de hoy
journalctl --list-boots                 # boots del sistema
```

## Puntos clave

- Cada proceso tiene un PID. ps aux lista todos, top/htop monitorean en vivo.
- Señales: SIGTERM (15) educado, SIGKILL (9) forzado. Intenta primero TERM.
- systemd gestiona servicios: systemctl start/stop/enable.
- journalctl lee los logs. -f para follow, -u para servicio específico.
